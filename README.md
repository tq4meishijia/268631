## 1. 项目简介

本仓库是一个**面向多人协作的知识沉淀平台**，将散落在课程作业、调研、访谈与汇报过程中的公开信息、方法论与结论，整理为结构统一、可检索、可复用的文档资产。

仓库设计遵循三条主线：

1. **知识可复用** — 把一次性成果沉淀为可检索、可引用的资料，降低重复调研与制作成本。
2. **协作可并行** — 以统一的目录约定、贡献流程与维护规则，支撑多成员同时补充与修订。
3. **来源可追溯** — 政策类文档保留官方原文与出处说明，便于后续核校与版本更新。

> **重要说明**：本仓库是**资料库**，不是可运行程序。它没有依赖、没有构建步骤、没有测试套件；「安装」即 `git clone`，「使用」即阅读与检索。

## 2. 功能特性

| 特性 | 说明 |
| --- | --- |
| **统一目录规范** | 唯一内容根 `knowledge/`，二级目录 `NN_名称`（两位序号 + 语义化中文名），杜绝目录漂移 |
| **多格式资料** | 支持 Markdown、TXT、HTML、DOCX、PPTX、PDF、SVG、CSV、JSON、YAML 等常见格式 |
| **来源可追溯** | 政策类文档保留官方原文摘录、文件名或发布链接，结论可回溯至出处 |
| **时效标记** | 政策类文档标注适用年份/版本；失效内容加「已过时」标记而非删除 |
| **脱敏就绪** | 纳入文件的正文、元数据与提交信息已统一脱敏，不含个人身份信息 |
| **静态可浏览** | 部分子目录提供可直接用浏览器打开的静态导览页，零外部依赖 |
| **模板与素材** | 提供校方 VI 矢量素材、通用演示模板及质检报告，可直接复用 |
| **AI 协作友好** | 目录与命名规范机器可读，便于 AI agent 定位、索引与增量维护 |

- Agent 工具数据（`.workbuddy/`、`.slidep/`、`.cache/` 等）与转换/构建产生的隐藏临时目录。

- 草稿、旧版本、中间态 PPT、解包产生的 XML / RELS、位图与压缩包。
- 超过 50 MB 的单文件、含大量第三方联系方式的简介汇编、个人医疗记录。
- 目录规范化产生的本地回退快照（`.file-org-undo/`）与回收区（`.file-org-trash/`）。

## 7. 协作方式

1. **分支**：默认分支 `main` 保持稳定；所有改动通过功能分支 + Pull Request 合入。
2. **Issue**：用 Issue 记录资料勘误、补充需求与来源更新，标题采用 `[类别] 简述`。
3. **评审**：至少一位其他成员 Review 后合入；政策类改动需注明来源链接或官方文件名。
4. **冲突**：同一文档的并行修改先在 Issue 中协调，避免互相覆盖。
5. **大文件**：单文件建议 < 20 MB，超过 50 MB 不纳入（GitHub 单文件上限 100 MB）。确需大文件时先在 Issue 中讨论外链或 Git LFS 方案。

## 8. 维护约定

- **事实与观点分离**：政策原文保持原样；整理稿中明确标注推断、假设与适用范围。
- **时效标记**：政策类文档在标题或首行注明适用年份 / 版本；失效内容不删除，在文件内加「已过时」标记并在索引中说明。
- **来源可追溯**：每条制度性结论保留官方文件名或发布链接。
- **命名规范**：内容根目录固定为 `knowledge/`；二级目录统一 `NN_名称`；三级以下沿用既有序号或英文小写 kebab-case；禁止 `&`、全角括号、空格与中英混排缩写。目录结构调整须同步更新本文件 §4 与 `HANDOFF.md`。
- **脱敏纪律**：新增内容不得包含任何成员或被访者的学号、私人邮箱、手机号、微信号、宿舍号；姓名以「编者」或受访者代号代替。详见 §10。
- **提交信息**：格式为 `<type>: <summary>`（`type` ∈ `docs` / `fix` / `add` / `chore`），不写个人身份信息。
- **暂存纪律**：不要用 `git add -A`。本地工作区存在大量被忽略的过程产物，新增文件请显式指定路径。

## 9. 贡献指引

欢迎通过以下方式参与维护与补充：

**贡献流程**

1. Fork 或新建分支：`git checkout -b docs/<主题>`。
2. 只改动与主题相关的文件；二进制成品（PPTX / PDF）随附一段说明其改动的文字。
3. 提交前自检：
   - 文件名与内容不含个人身份信息；
   - 新增文件未被 `.gitignore` 意外忽略（`git check-ignore -v <path>`）；
   - Markdown 链接指向仓库内真实存在的路径。
4. 发起 PR，填写：改动内容、来源依据、是否影响既有结论。
5. 由维护者合并；若目录结构发生变化，同步更新本文件 §4。

**PR 标题建议**

```
docs: <简述本次改动>          # 文档新增或修订
fix: <简述本次修复>            # 勘误、链接修复
add: <简述新增内容>            # 新资料、新素材
chore: <简述维护操作>          # 目录调整、命名规范更新
```

**评审要点**

| 检查项 | 通过标准 |
| --- | --- |
| 准确性 | 政策类结论可回溯至官方来源 |
| 完整性 | 新增文件有对应索引或在本文件 §4 中体现 |
| 脱敏 | 无个人身份信息（学号、联系方式等） |
| 格式 | Markdown 链接有效，命名符合 §8 规范 |
| 范围 | 只改动与 PR 主题相关的文件 |
