# 268631 · 共享知识库

> 面向多人协作与知识共享的资料仓库：汇集学业政策调研、竞赛与推免路径整理、访谈与汇报方法，以及校方 VI 与演示模板资源。
>
> **仓库名 `268631` 是项目代号，与任何学号或个人编号无关。** 目录名中的 `631` 为小组编号，按约定原样保留。

## 1. 仓库目标

1. **沉淀可复用的知识**：把散落在课程作业、调研与汇报中的公开信息、方法论与结论整理为可检索的文档。
2. **支持多人协作**：提供统一的目录约定、贡献流程与维护规则，让多位成员可以并行补充与修订。
3. **共享模板与素材**：提供校方 VI 矢量素材、通用演示模板及其质检说明，降低重复制作成本。
4. **保持来源可追溯**：政策类文档保留官方原文与出处说明，便于后续核校与版本更新。

本仓库是**资料库**，不是可运行程序：没有依赖、没有构建步骤、没有测试套件。

- Agent 工具数据（`.workbuddy/`、`.slidep/`、`.cache/` 等）与转换/构建产生的隐藏临时目录。

- 超过 50 MB 的单文件、含大量第三方联系方式的简介汇编、个人医疗记录。

## 4. 快速开始

```bash
git clone https://github.com/<owner>/268631.git
cd 268631
```

- 纯文本资料可直接用编辑器或 GitHub 网页阅读。
- `学业事宜/web/*.html` 为静态页面，用浏览器直接打开即可，无外部依赖。
- PPTX / DOCX / PDF 用 Office、WPS 或 LibreOffice 打开；SVG 可用浏览器或矢量工具查看。
- 把 `<owner>` 替换为维护者的 GitHub 账号名。

## 5. 协作方式

1. **分支**：默认分支 `main` 保持稳定；所有改动通过功能分支 + Pull Request 合入。
2. **Issue**：用 Issue 记录资料勘误、补充需求与来源更新，标题采用 `[类别] 简述`。
3. **评审**：至少一位其他成员 Review 后合入；政策类改动需注明来源链接或官方文件名。
4. **冲突**：同一文档的并行修改先在 Issue 中协调，避免互相覆盖。
5. **大文件**：单文件建议 < 20 MB，超过 50 MB 不纳入（GitHub 单文件上限 100 MB）。确需大文件时先在 Issue 中讨论外链或 Git LFS 方案。

## 6. 维护约定

- **事实与观点分离**：政策原文保持原样；整理稿中明确标注推断、假设与适用范围。
- **时效标记**：政策类文档在标题或首行注明适用年份 / 版本；失效内容不删除，在文件内加「已过时」标记并在索引中说明。
- **来源可追溯**：每条制度性结论保留官方文件名或发布链接。
- **命名**：沿用现有「序号_主题_状态」风格；新增目录使用两位序号前缀；文件名避免除下划线、连字符外的特殊字符。
- **脱敏纪律**：新增内容不得包含任何成员或被访者的学号、私人邮箱、手机号、微信号、宿舍号；姓名以「编者」或受访者代号代替。详见 §8。
- **提交信息**：格式为 `<type>: <summary>`（`type` ∈ `docs` / `fix` / `add` / `chore`），不写个人身份信息。
- **暂存纪律**：不要用 `git add -A`。本地工作区存在大量被忽略的过程产物，新增文件请显式指定路径。

## 7. 贡献规范

1. Fork 或新建分支：`git checkout -b docs/<主题>`。
2. 只改动与主题相关的文件；二进制成品（PPTX / PDF）随附一段说明其改动的文字。
3. 提交前自检：
   - 文件名与内容不含个人身份信息；
   - 新增文件未被 `.gitignore` 意外忽略（`git check-ignore -v <path>`）；
   - Markdown 链接指向仓库内真实存在的路径。
4. 发起 PR，填写：改动内容、来源依据、是否影响既有结论。
5. 由维护者合并；若目录结构发生变化，同步更新本文件 §3。

## 8. 隐私与脱敏约定

- 初始化时对全部纳入文件的正文、文件名、目录名、Office 文档元数据与提交信息做过统一脱敏：原作者署名替换为 `〔已脱敏〕`，文档作者元数据统一为 `268631 Contributors`。
- **保留项**：`268631`（仓库代号）、目录名中的 `631`（小组编号）、公开的学校 / 学院 / 专业名称，均不属于个人身份信息，按约定保留。
- **第三方信息**：采访对象与公开资料中出现的第三方姓名、公开联系方式按当前维护口径保留。若需进一步匿名化，请在 Issue 中提出并统一处理（同时复核历史提交）。
- **已知边界**：位图与非文本素材未纳入仓库；Office / PDF 内嵌图片中的可见文字未做 OCR 校验。
- 详细的复核口径、残留说明与后续任务见 `HANDOFF.md` §4–§5。
